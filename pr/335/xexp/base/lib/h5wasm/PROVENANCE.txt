h5wasm — vendored WebAssembly HDF5 (reads/writes .slp / .h5 in the browser)

Source:  npm `h5wasm@0.10.3`  (https://www.npmjs.com/package/h5wasm)
Pinned:  0.10.3
Added:   PR 5.2b (h5wasm consolidation) — replaces the mixed CDN 0.8.8 /
         CDN 0.10.2 / local ~0.10 setup with a single local 0.10.3.

Files (from the npm tarball's dist/):
  hdf5_hl.js      <- dist/esm/hdf5_hl.js    ESM entry (imports ./hdf5_util.js).
                     Used via the index.html importmap (`h5wasm`) by sleap-io.js's
                     main-thread materialization, and by relative import in the
                     module workers (loading/slp-import-worker.js, frame-worker.js).
  hdf5_util.js    <- dist/esm/hdf5_util.js  Emscripten glue + embedded wasm (no
                     sidecar .wasm to serve).
  h5wasm.iife.js  <- dist/iife/h5wasm.js    Self-contained IIFE (global `h5wasm`).
                     Used by the index.html <script> tag (points3d read/write via
                     initH5wasm) and passed as `h5wasmUrl` to readSlpStreaming's
                     importScripts worker.

Not vendored: dist/esm/file_handlers.js (not in hdf5_hl.js's import graph),
dist/node/* (Node build).

Rebuild/bump: `npm pack h5wasm@<version>`, then copy dist/esm/{hdf5_hl,hdf5_util}.js
and dist/iife/h5wasm.js here; re-verify every reader (points3d R/W, analysis-H5,
embedded-frame extraction, SLP) since 0.10.x changed some APIs (e.g. removed
`create_compound_dataset`).
